Technical Algorithm / System Details

CRNN (Convolutional Recurrent Neural Network) Architecture

CRNN Workflow

1
Input Image Processing
Nutrition label or expiry date image is fed into the network
2
CNN Feature Extraction
Convolutional layers extract spatial features → feature map
3
RNN Sequence Modeling
Handles varying text length and sequential dependencies
4
Output & Decoding
Probability distribution → CTC decoded into final text

Algorithm Pseudo Code & Complexity

CRNN with CTC Decoding Implementation

CRNN Pseudo Code
Input: Image I of size H x W
1. F ← CNN(I) // Extract features
2. S ← reshape(F) // Convert feature map into sequence
3. H ← RNN(S) // Sequence modeling with hidden states
4. P ← Softmax(H) // Output probability distribution
5. Y ← CTC_Decode(P) // Decode sequence into final text
Output: Predicted text Y

Complexity Analysis

CNN feature extraction:
O(H × W × k²) where k = kernel size
RNN sequence modeling:
O(T × h²) where T = sequence length, h = hidden units
CTC decoding:
O(T × |C|) where |C| = character set size

Performance Characteristics

✅ Efficient
For medium-length text sequences
⚠️ Less Scalable
For very long text sequences
🔥 Training Complexity
Higher due to combined CNN + RNN + CTC pipeline

CRNN vs Alternatives

Comparative Analysis of OCR Approaches

Aspect CRNN YOLO + OCR Transformer-based OCR
Variable-length text ✅ Excellent ⚠️ Limited ✅ Excellent
Structured text recognition ✅ Good ✅ Good ✅ Excellent
Deployment weight ✅ Lightweight ✅ Fast ❌ Heavy
Curved/glossy text ❌ Struggles ❌ Poor ✅ Superior
Small fonts ❌ Poor accuracy ⚠️ Limited ✅ Better
Multilingual support ⚠️ Weaker ⚠️ Limited ✅ Superior

Where CRNN is Better

  • Handles variable-length text sequences (expiry dates, nutrition panels)
  • Performs well on structured text recognition in small vocabularies
  • Lightweight compared to Transformers → easier mobile deployment
  • Good balance of accuracy and computational efficiency

CRNN Limitations

  • Struggles with curved/glossy packaging (distorted input)
  • Small fonts → poor recognition accuracy
  • Multilingual recognition → weaker than Transformer-based OCR
  • Slower than YOLO + OCR for simple region detection tasks
